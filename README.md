# МедКиоск

Система мониторинга и обслуживания киосков предрейсовых медицинских осмотров.

**Киоск (ПАК)** — самостоятельная станция с алкотестером, тонометром и термометром,
которая проводит предрейсовые медосмотры водителей. Система следит за состоянием
этих киосков, ведёт учёт ремонтов, поверок средств измерений и заявок, рассылает
уведомления в Telegram и предоставляет отчёты.

---

## Технологии

- **Backend:** Django 5.x, PostgreSQL 16
- **Frontend:** Bootstrap 5.1 (локально), Bootstrap Icons, тёмная тема
- **Бот:** python-telegram-bot
- **Телеметрия:** MQTT (paho-mqtt)
- **Деплой:** Docker Compose (nginx + gunicorn), SQLite для тестов

## Функциональность

### Веб-приложение
- **Дашборд киосков** — все киоски на одной странице; поиск по номеру;
  кнопки фильтра статуса (Все / Онлайн / Оффлайн / В ремонте).
- **Карточки киосков** — онлайн/оффлайн, длительность простоя, VPN/AnyDesk,
  объект/владелец/локация, мед.индикаторы (алко ✅ / тоно ✅),
  метрики CPU/HDD/RAM, прогресс ремонта, срок поверки, детальный блок по клику.
- **Живое обновление** — карточки и статистика обновляются раз в 5 сек;
  при появлении оффлайн — уведомление в заголовке вкладки.
- **История событий** — аудит переходов статуса киоска и ремонтов,
  фильтр по типу, номеру и дате.
- **SSH к киоскам** — перезагрузка, стоп/старт сервиса и загрузка файлов
  (SCP). Подключение пробует несколько паролей: свой у киоска, общий,
  резервные из `DEVICE_SSH_PASSWORDS`.
- **Объекты** — страница организаций, где стоят киоски, со списком устройств.
- **Админка Django** (`/admin/`) — управление киосками, ролями, поверками,
  заявками, отправками, ремонтами, поездками; журнал аудита только на чтение.
- **Отчёты (Excel)** — списки киосков, история, статистика, алко/тоно,
  поверки сроками, «Мед.средства», сводка по киоску.
- **Аналитика доступности** — % uptime каждого киоска за неделю/месяц,
  считается из истории событий (онлайн/оффлайн).
- **Поверки со сроками** — связь с киоском, «Действует до», индикация
  (в сроке / скоро истекает / истекла), напоминания в Telegram.
- **Мобильная версия** — отзывчивые таблицы и управление.

### Telegram-бот
- Меню по кнопкам с эмодзи (по ролям).
- Создание / просмотр / поиск / редактирование заявок, статус киоска.
- Регистрация и привязка аккаунта.
- **`/adduser`** — добавление пользователей (нужно право «Может добавлять
  пользователей через бот» в админке), с выбором роли.
- **`/password`** — смена пароля аккаунта напрямую в личке, без администратора.
- **`/unlink`** — отвязать Telegram.
- Автоматические уведомления: киоск оффлайн/онлайн, сроки поверок,
  ежедневная/еженедельная сводка, health-check.

### Роли
- **Техник** — создаёт и редактирует свои заявки.
- **Наблюдатель** — видит все заявки и статистику.
- **Админ** — всё + панель управления, добавление пользователей через бот.

## Быстрый старт (локально)

```bash
# 1) окружение
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt

# 2) секреты
cp .env.example .env      # заполни реальные значения

# 3) БД и миграции (для локального dev можно включить sqlite в settings)
python manage.py migrate
python manage.py createcachetable
python manage.py createsuperuser

# 4) запуск
python manage.py runserver   # сайт: http://localhost:8000
```

Отдельные сервисы запускаются так:
```bash
python manage.py mqtt_listener2        # телеметрия с киосков
python manage.py telegram_bot          # Telegram-бот
python manage.py check_verifications   # напоминания о сроках поверок
```

## Запуск на сервере (Docker)

Требуется: Docker + Docker Compose, `.env` в корне проекта, сертификаты
Let's Encrypt для nginx (монтируются из `/etc/letsencrypt`).

```bash
# перенос (если не используешь deploy.sh) и полная пересборка:
docker compose down
docker compose up -d --build

# проверка:
docker compose ps
docker compose logs --tail=30 web bot mqtt_listener
```

Ключевые настройки в `docker-compose.yml`:
- `web` стартует с `migrate` → `createcachetable` → `collectstatic` → `gunicorn`; healthcheck HTTP.
- `db`, `nginx`, `bot`, `mqtt_listener` — с healthcheck и правильным порядком старта.
- `web`/`bot`/`mqtt_listener` получают `DB_HOST=db` (не `localhost`).

### Автоматический деплой одной командой

```bash
./deploy.sh
```
Синхронизирует проект (rsync, включая `.env`), пересобирает, показывает
`docker compose ps` и логи. Без локального `.env` не запустится.

### Cron (обязательно для напоминаний о поверках)

```cron
0 10 * * * cd /root/devicehub && docker compose exec -T web python manage.py check_verifications
```

### Бэкапы БД

```bash
./backup.sh        # создать дамп в backups/ и удалить старше KEEP_DAYS (14 по умолчанию)
./restore.sh backups/devicehub_YYYYMMDD_HHMM.dump   # восстановить из дампа
```

Бэкап проверяет целостность дампа (`pg_restore -l`) и не сохраняет повреждённые файлы.
Поставьте в cron ежедневный бэкап, например:

```cron
30 1 * * * cd /root/devicehub && ./backup.sh >> /var/log/devicehub-backup.log 2>&1
```

Каталог `backups/` исключён из репозитория (см. `.gitignore`). Перед восстановлением
рекомендуется сделать свежий бэкап текущего состояния.
